Releases and upgrading

How versions are numbered, and what taking a new one involves.

Versioning

The kit follows Semantic Versioning and records every change in CHANGELOG.md, using the Keep a Changelog format.

  • A minor release may add tables, enum cases and route names. It won't rename existing ones.
  • A major release is the only kind that renames things.

Upgrading to the next major

If you're starting a project from the current branch, there's nothing to do. If your project is built on 1.2.0, the following were renamed and need replacing throughout your code:

WasIs
users.typeusers.user_type
user_roles tablerole_user pivot
UserRoleEnumUserTypeEnum
ImageVisibilityEnumMediaVisibilityEnum (stored values unchanged)
admin.membersadmin.users
admin.site-configadmin.config.site
<x-status><x-util.e-badge>

Role assignments don't carry across, because the old pivot held a status column and the new one doesn't. Re-assign them from Admins → Manage roles. After that, start the scheduler, because four of the scheduled commands are new.
