Releases and upgrading

How versions are numbered, and what taking a new one involves.

Versioning

The kit follows Semantic Versioning and records every change in CHANGELOG.md, using the Keep a Changelog format.

  • A minor release may add tables, enum cases and route names. It won't rename existing ones.
  • A major release is the only kind that renames things.

If you're starting a project from the current kit, there's nothing to do. The sections below are for a project built on an earlier version.

Upgrading to 2.7.0

There are no new tables. One new dependency, league/flysystem-aws-s3-v3 (guzzle stays on 8), and new views, so install and rebuild: 

composer install
npm install && npm run build

The kit indexes images.disk by editing its create migration. A project made from the kit needs its own add_* migration for it: 

Schema::table('images', function (Blueprint $table) {
    $table->index('disk');
});

This minor release renames two routes and two gate keys, which a minor normally doesn't. Both email screens became one, so there was no way to keep the old names pointing anywhere useful.

WasNow
admin.config.email-sendersadmin.config.email-settings.sender
admin.config.email-deliveryadmin.config.email-settings.delivery
Gates config.email-senders, config.email-deliveryGate config.email-settings
  • Search your own code for the two old route names and replace them.
  • A custom role that held either old gate key needs config.email-settings granted on Roles. A role holding config needs nothing.
  • Delete any public/robots.txt you added. The web server serves a static file before the app's.
  • Every visitor sees the cookie banner once more, since the old notice's dismissal isn't a site_consent answer.
  • Analytics and R2 are both off until you set them up. A role holding only some config.* children needs config.file-storage granted to reach File storage.

Upgrading to 2.6.0

There are no migrations and no renames. Install the dependencies and rebuild the assets, since there are two new JS modules and new CSS:

composer install
npm install && npm run build

Lower-case the stored email addresses, or some accounts can't sign in. Every lookup now normalises the typed address, so a row still stored as John@Example.com isn't found on SQLite or PostgreSQL. Two rows that differ only by case would collide on the unique index, so look for those first in php artisan tinker:

use App\Models\User;
use Illuminate\Support\Facades\DB;

DB::table('users')->whereNotNull('email')->get(['id', 'email'])
    ->groupBy(fn ($row) => User::normalizeEmail($row->email))
    ->filter(fn ($rows) => $rows->count() > 1);

Merge or rename any it finds, then lower-case the rest:

DB::table('users')->whereNotNull('email')->orderBy('id')->each(
    fn ($row) => DB::table('users')->where('id', $row->id)
        ->update(['email' => User::normalizeEmail($row->email)])
);
  • DB::table() is on purpose: it reaches soft-deleted rows and fires no model events. MySQL's default collation already ignores case, but run it there too so the stored shape is the same everywhere.
  • Members no longer see site media. A member's library and pickers now hold only what that member uploaded. If your project shared images or videos with members by marking them public or by account type, that has stopped. Offer that media another way, or bring back the old visibleTo and browsableBy scopes from the 2.5.0 tag in your own copy.
  • Check WebP before going live. New JPEG and PNG uploads are saved as WebP, and existing files aren't touched. Desktop Outlook can't show WebP, so if library images go out in email, turn off Convert photos to WebP under Configuration › Security. php -r "var_dump(function_exists('imagewebp'));" tells you whether the server can convert at all.
  • The brand colour needs nothing. The default is the teal the kit was built with, and nothing is printed for it. If your own email views hard-code #2DD4B5, use kBrandColor() so they follow the setting. A role holding config reaches the new screen. A role holding only some config.* children needs config.brand-colors granted on Roles.
  • The Translate this page menu is off. If you turn it on, mention Google's translator and its googtrans cookie in your cookie and privacy policies.

Upgrading to 2.5.0

Run the migrations. They add the payment_subaccounts table and a payment_subaccount_id column on transaction_gateways:

php artisan migrate

The kit adds the column by editing its create migration. A project made from the kit needs its own add_* migration for it, dated after the payment_subaccounts one: 

Schema::table('transaction_gateways', function (Blueprint $table) {
    $table->foreignId('payment_subaccount_id')->nullable()->after('vendor')
        ->constrained()->nullOnDelete();
});

Move the stored gate keys, or every role loses the money screens. That includes the seeded Administrator role. Transactions, Payments and Subscriptions now sit under Finance, and their gates moved from transactions, payments and subscriptions to finance.transactions, finance.payments and finance.subscriptions. Roles and admin overrides keep their gates in the database, so run this once in php artisan tinker or a one-off migration:

use App\Models\Role;
use App\Models\User;
use App\Services\RoleService;

$moved = ['transactions', 'payments', 'subscriptions'];

foreach ([Role::query(), User::query()] as $query) {
    $query->whereNotNull('gates')->each(function ($row) use ($moved) {
        $gates = $row->gatesArray();

        foreach ($moved as $key) {
            if (array_key_exists($key, $gates)) {
                $gates["finance.{$key}"] ??= $gates[$key];
                unset($gates[$key]);
            }
        }

        $row->gates = $gates;
        $row->saveQuietly();
    });
}

// The Administrator role is meant to reach everything, Subaccounts included.
$administrator = app(RoleService::class)->protectedRole();
$administrator->gates = [...$administrator->gatesArray(), 'finance.subaccounts' => 'full'];
$administrator->saveQuietly();
  • Each role keeps its level, and a denial in an admin's override stays a denial. No other role is given Subaccounts. Grant it on Roles on purpose.
  • Search your own code for the old keys (kGate('transactions', setPageGate('payments', kSetSiteTitle('subscriptions')) and add the finance. prefix. A title takes the group first: kSetSiteTitle('finance', 'payments').
  • Add APP_REPOSITORY_URL and APP_DOCUMENTATION_URL to .env, each either your own or empty to remove its links. Left unset, they point at the kit's repository and these docs.
  • If the config is cached, rebuild it with php artisan config:cache.

Upgrading to 2.4.0

Run the new migration and seed the regions:

php artisan migrate
php artisan db:seed --class=RegionSeeder

An install that sends email today stops until a provider is picked. The new Email delivery screen overrides MAIL_MAILER and starts on Log only. Straight after deploying, open Site configuration → Email delivery, pick your provider (SMTP for an existing MAIL_MAILER=smtp setup), save, and send a test.

  • If your project implements SupportsSubscriptions on a gateway of its own, add resumeSubscription(). A vendor that can't resume returns a sentence saying so, as PaypalGatewayService does.
  • For Resend or Brevo, add RESEND_API_KEY or BREVO_API_KEY. For Bachs, add BACHS_SECRET_KEY, plus BACHS_WEBHOOK_SECRET in production.
  • International fees start off and no home country is set, so nothing customers pay changes until you set them.
  • If the config is cached, rebuild it with php artisan config:cache.

Upgrading to 2.3.0

There are no migrations. Rebuild the front end:

npm run build

Convert the stored policy and FAQ text to HTML, once. An existing install holds it as markdown, and the public pages now print it as HTML. Run this in php artisan tinker or a one-off migration. It doesn't touch updated_at, so the date on a legal page stays the same: 

use App\Services\BlogService;
use App\Services\MarkdownService;
use Illuminate\Support\Facades\DB;

$toHtml = fn (?string $markdown) => app(BlogService::class)->sanitize(app(MarkdownService::class)->toHtml($markdown));

DB::table('faqs')->orderBy('id')->each(fn ($row) => DB::table('faqs')->where('id', $row->id)->update(['answer' => $toHtml($row->answer)]));
DB::table('policies')->orderBy('id')->each(fn ($row) => DB::table('policies')->where('id', $row->id)->update(['content' => $toHtml($row->content)]));

Run it once only. MarkdownService escapes raw HTML, so a second run turns the converted text back into visible tags.

  • Changes you made to the old pages::site.home or pages::site.blog.* Livewire pages move to resources/views/site/ and the matching Site\ controller.
  • <x-form.markdown-field>, kMarkdownFormat() and .markdown-prose are gone. Use <x-form.rich-text>, save through BlogService::sanitize(), and style with .rich-prose.
  • Existing lime-* classes still render correctly. Write new ones as brand-*.
  • Processing fees start at zero, so nothing customers pay changes until you set one. See Payments.

Upgrading to 2.2.1

Nothing to migrate. If the config is cached, rebuild it so the new payments log channel is registered:

php artisan config:cache

Upgrading to 2.2.0

php artisan migrate

That creates the payment and subscription tables. transaction_gateways needs five columns by hand, because they were folded into its create migration, which an existing install has already run. Add them in a migration of your own: 

Schema::table('transaction_gateways', function (Blueprint $table) {
    $table->string('currency', 10)->nullable()->after('vendor');
    $table->string('channel', 100)->nullable();
    $table->string('failure_reason')->nullable();
    $table->timestamp('paid_at')->nullable();
    $table->timestamp('verified_at')->nullable();
});

The kit's other add_* migrations were folded into their create_*_table files too, but those columns already exist on a 2.1.0 install. Don't run migrate:fresh to catch up.

  • Copy the payments block from .env.example, fill in the vendors you'll use, and run php artisan payments:health.
  • Register https://your-site/webhooks/payments/{vendor} in each vendor's dashboard.
  • Run a queue worker and the scheduler. Three scheduled commands are new.
  • Replace the example SubscriptionFeatureEnum cases before creating plans.
  • Grant the payments and subscriptions gates to the roles that need them.

See Payments and subscriptions.
