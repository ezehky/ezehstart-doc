Workspaces and user types

An account's type decides which workspace it signs in to. It's fixed in code, and it isn't the same thing as a role.

The workspaces

Defined in bootstrap/app.php:

WorkspaceURL prefixRoute nameRoute fileMiddleware
Admin/app-splashadmin.routes/admin.phpAdminMiddleware
Member/appuser.routes/user.phpUserMiddleware
Public + auth/(none)routes/web.phpguest / auth

Some screens are shared, such as the profile and the image and video libraries. They live under pages::shared.* and are routed from both workspace files.

Type is not role

users.user_type is the workspace an account signs in to, and it's fixed in code by UserTypeEnum. A role is a row in roles that an administrator creates from the dashboard. Roles only divide up the admin workspace, and only admins have them. Members have no role at all.

Every decision that depends on type (the dashboard route, the label, whether it carries roles) is a method on the enum case. When you add a case, the exhaustive match arms fail loudly until you've handled it.

UserTypeEnum::dashboardRoute() returns a URL, not a route name. Pass it to redirect()->to(). redirect()->route() throws.
