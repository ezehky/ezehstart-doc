Impersonation

An administrator can view the site as a member, because "the button doesn't work" can't be diagnosed from the outside. It's also the most dangerous thing an admin can do, so it's built on the assumption that it will one day be abused or left running.

The rules

  • Never admin to admin. Becoming a peer would be privilege escalation with a support story attached.
  • The real identity lives in the session, never in a signed URL or a query parameter, because a token in a link gets copied, logged and replayed.
  • Both ends are logged as the administrator, so the trail reads "X started acting as Y".
  • It expires after an hour.
  • Every screen that changes the account is closed while it runs. Impersonation is for looking.

To end a session, visit /stop-impersonating.

Writing screens that respect it

Impersonation replaces the signed-in account, so nothing about the request identifies the admin any more. ImpersonationService::isImpersonating() is the only way to tell. While it runs, the session passes UserMiddleware and never AdminMiddleware, which is why the hour expiry is checked in UserMiddleware.

Any new screen that changes an account rather than just showing it needs this in mount():

abort_if(app(ImpersonationService::class)->isImpersonating(), 404);

The security, delete-account and download-data screens already do this.
