What it is

Ezeh Start is a starter kit, not an application. It ships authentication, roles, two workspaces, account management, image and video libraries, a blog, email marketing, a transaction ledger, and versioned legal pages. It contains nothing domain-specific: every model, enum, service and screen in it is one you'd keep in almost any project.

What makes it different from a blank laravel new is the second half: a library of written conventions in .agents/my-skills/. It covers where each kind of code lives, how it's named, and which Laravel defaults the project deliberately doesn't use. Humans and AI agents read the same rules, so work added by either lands in the same shape.

What ships

AreaIn short
AuthenticationPassword, passwordless codes, passkeys, social sign-in, TOTP two-factor, password history, a login throttle, and a Turnstile captcha
WorkspacesAn admin workspace at /app-splash and a member workspace at /app, each with its own middleware and routes
RolesRoles are rows an admin creates. Their gate maps merge, and the highest access wins each key
AccountsDeletion with a grace period and reminders, anonymize-or-remove, restore, and a download of the data held on an account
ImpersonationAn admin views the site as a member. The session is logged, expires after an hour, and blocks every screen that changes the account
MediaImage and video libraries with folders, per-item visibility, and a delete guard backed by usage tables
BlogTiptap editor, polymorphic categories and tags, scheduled posts, an Author role with public bylines
MoneyA transaction ledger whose balances are derived, never stored, plus multi-currency display
EmailA block-based template builder, campaigns with recurrence, a newsletter with no extra table, and system emails an admin can override
Legal pagesTerms, privacy and cookie pages, versioned, with consent recorded against the exact version
Data tablesOne trait for selection, bulk actions, column manager, sorting, date ranges, and CSV/XLSX/PDF export and import
AuditEvery admin write is logged with what changed and what it changed from

Who it's for

Teams and solo developers starting a Laravel product who would rather begin with auth, an admin, auditing and legal pages already built, and who are happy to follow a set of written opinions in exchange. If you want a minimal skeleton with no conventions, a plain Laravel install will suit you better.
