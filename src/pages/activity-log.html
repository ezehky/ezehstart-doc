Activity log

Every admin write records what changed and what it changed from.

Logging a write

This is mandatory for every admin write. Capture the changed columns before saving, and log after:

$log = app(ActivityLogService::class);

$changes = $log->affectedColumns($post);
$post->save();

$log->logActivity(ActivityActionEnum::UPDATE, 'updated a post', $changes, $post);

See .agents/my-skills/activity-logging.md for the exact signature and the action and platform enums.

Retention

Off by default. security.activity-log-retention-days starts at 0, and activity:prune-logs does nothing until someone sets a window. Throwing away an audit trail should be a deliberate decision. Any value above 0 is floored at 30 days. 

php artisan activity:prune-logs --dry-run    # what would go
php artisan activity:prune-logs --days=90    # prune once, without changing the setting

Notifications

In-app notifications are database notifications whose types are rows, not code, so a new type can be added without a deploy. Every account gets a switch for it on their next visit, and announcements are sent to everyone subscribed to a type.
