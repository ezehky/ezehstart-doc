Configuration

Configuration comes in two layers: .env for secrets and infrastructure, and a site configuration that administrators edit from the dashboard, with no deploy needed.

Environment keys

The standard Laravel keys apply. These are the ones specific to the kit:

KeyPurpose
GOOGLE_CLIENT_ID / _SECRETGoogle sign-in
FACEBOOK_CLIENT_ID / _SECRETFacebook sign-in
GITHUB_CLIENT_ID / _SECRETGitHub sign-in
TURNSTILE_SITE_KEY / TURNSTILE_SECRET_KEYCloudflare Turnstile captcha. The captcha switch has no effect until both are set
LARAVEL_PDF_DRIVERdompdf by default, which needs nothing installed. Other laravel-pdf drivers need their own packages

The example environment uses the database driver for sessions, queue and cache, and log for mail, so a fresh clone runs with nothing extra installed.

Site configuration

Everything an administrator should be able to change without a deploy is stored in a JSON file on the local disk, not in a table. It's edited under Admin → Site configuration:

ScreenHolds
InfoSite name, branding, logo, support contacts
SecuritySign-in switches, password policy, captcha, passkeys, activity-log retention
PreferencesNewsletter placements, cookie notice, mobile floating menu, account deletion window, data download
Social handles, currencies, email senders, notification types, logsOne screen each
JSON editorAny key that no screen has a field for yet

Reading configuration in code

kSiteConfig('group', 'key', $default);   // a value
kSiteFlag('group', 'key', $default);     // an on/off switch

Never read a switch with kSiteConfig(). Its default applies to any falsy value, so a switch someone deliberately turned off reads back as its default. kSiteFlag() checks whether the key is present instead.

kSiteConfig() is never empty after boot, because the cache layer adds the resolved logo and support keys. To find out whether a configuration has actually been saved, use app(SiteConfigurationService::class)->getConfigs(raw: true).

Defaults worth knowing

SwitchDefault
Strong passwords, password history, passwordless sign-inOn
Two-factor, social sign-in, captchaOff
Account deletion, anonymize after deletion, data downloadOn
Mobile floating menuOff
Activity-log retentionOff (0 days, which keeps everything)

Every switch closes its route as well as hiding its button. A route left reachable behind a hidden link isn't really disabled.
