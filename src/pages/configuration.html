Configuration

Configuration comes in two layers: .env for secrets and infrastructure, and a site configuration that administrators edit from the dashboard, with no deploy needed.

Environment keys

The standard Laravel keys apply. These are the ones specific to the kit:

KeyPurpose
GOOGLE_CLIENT_ID / _SECRETGoogle sign-in
FACEBOOK_CLIENT_ID / _SECRETFacebook sign-in
GITHUB_CLIENT_ID / _SECRETGitHub sign-in
TURNSTILE_SITE_KEY / TURNSTILE_SECRET_KEYCloudflare Turnstile captcha. The captcha switch has no effect until both are set
RESEND_API_KEY / BREVO_API_KEYEmail through Resend or Brevo, once picked on Email settings › Delivery. SMTP uses the standard MAIL_* keys
R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET, R2_ENDPOINT, R2_PUBLIC_URLCloudflare R2 for uploads, once switched on under File storage. The endpoint is https://<account-id>.r2.cloudflarestorage.com. The public URL is the bucket's r2.dev address or a custom domain, and the File storage screen can set it instead
APP_REPOSITORY_URL / APP_DOCUMENTATION_URLWhere the GitHub and docs links in the public header, the footer and the dashboard sidebar point. They default to the kit's repository and these docs. Set your own, or set one empty to remove its links
LARAVEL_PDF_DRIVERdompdf by default, which needs nothing installed. Other laravel-pdf drivers need their own packages

The example environment uses the database driver for sessions, queue and cache, and log for mail, so a fresh clone runs with nothing extra installed. The mail service actually used is picked on Email settings › Delivery, which overrides MAIL_MAILER.

Site configuration

Everything an administrator should be able to change without a deploy is stored in a JSON file on the local disk, not in a table. It's edited under Admin → Site configuration:

ScreenHolds
InfoSite name, branding, logo, support contacts, and the Google Analytics measurement ID. See Google Analytics
SecuritySign-in switches, password policy, captcha, passkeys, upload limits and WebP conversion, activity-log retention
PreferencesNewsletter placements, the cookie banner, the Translate this page menu and its languages, mobile floating menu, account deletion window, data download
Brand colourThe site's accent: one of six presets (teal, sky, indigo, violet, rose, amber) or any hex. See Brand colour below
Contact locationsOffices, branches or desks for the home page's contact section: a label, an address, any number of phones and emails, and an optional map. A map must be a Google Maps or OpenStreetMap embed. You can paste the whole <iframe> or just its src. An empty list hides the section
Email settingsTwo tabs. Sender: the from-addresses. Delivery: which service sends the site's email, the log, Resend, Brevo or SMTP. Keys stay in .env. See Email
File storageWhether uploads go to Cloudflare R2, the bucket's public address, and a batched sync. Keys stay in .env. See File storage
Social handles, currencies, notification types, logsOne screen each
JSON editorAny key that no screen has a field for yet

Reading configuration in code

kSiteConfig('group', 'key', $default);   // a value
kSiteFlag('group', 'key', $default);     // an on/off switch

Never read a switch with kSiteConfig(). Its default applies to any falsy value, so a switch someone deliberately turned off reads back as its default. kSiteFlag() checks whether the key is present instead.

kSiteConfig() is never empty after boot, because the cache layer adds the resolved logo and support keys. To find out whether a configuration has actually been saved, use app(SiteConfigurationService::class)->getConfigs(raw: true).

Brand colour

One build serves every project made from the kit. BrandColorService takes the one colour picked, places it on brand-400, derives the other ten shades around it in OKLCH, and the base layout prints them as CSS variables after the compiled stylesheet. Every brand-* utility, Flux's accent and the email builder's brand swatch follow it. Nothing is rebuilt.

  • For the teal app.css was compiled with, nothing is printed.
  • Button text is worked out per colour: white where it reaches 3:1, dark otherwise. The preview warns when it falls below 4.5:1.
  • The setting lives in brand.palette and brand.primary. A preset's hex comes from BrandPaletteEnum, so primary only matters for Custom.
  • The gate is config.brand-colors. It inherits config.
kBrandColor();      // the 400 shade as a hex, for email
kBrandColor(700);   // any shade, 50 to 950

On a page, use brand-* classes. They follow the setting already. Reach for kBrandColor() only where a CSS variable can't, which mostly means email.
