The house style

The kit is opinionated, and its opinions are written down so that everything added later looks like it was part of the original.

Where it lives

.agents/my-skills/ is a library of more than forty files covering where code goes, how it's named, and what the project deliberately doesn't use.

agent.mdRead before writing any code. The ten laws, the hard bans, and the generation procedure
README.mdThe index, which maps a task to the file that covers it
checklist.mdWalk it before reporting done. The review gate
templates.mdEvery copy-paste template in one place

AI agents get the same rules automatically. CLAUDE.md orients a session, AGENTS.md carries the Laravel Boost guidelines, and the house-style skill in .claude/skills/ (mirrored to .agents/ and .github/) routes an agent into the library. Where the two overlap, the house style wins: it describes this project, while Boost describes Laravel in general.

The short version

  • Screens are Livewire single-file components at resources/views/pages/**/⚡name.blade.php, routed with Route::livewire('/path', 'pages::group.name'). There's no app/Livewire folder and no class-based components.
  • Validation lives in protected function rules(): array. Don't use #[Validate] or a $rules property.
  • Models are #[Unguarded], with a casts() method and #[Scope] scopes. Don't use $fillable or scopeFoo().
  • Business logic lives in #[Singleton] services, resolved with app() and never with new.
  • Every status is an enum using WithEnumHelpers, with one is{Case}() method per case.
  • Every admin write is logged: call ActivityLogService::affectedColumns() before save(), then logActivity() after.
  • Every action is gated twice (see Roles and gates).
  • Every destructive action is confirmed with <x-dashboard.confirm-modal>, never wire:confirm.
  • No logic in views. Queries, services and flags go in a page #[Computed] property backed by a service. Components take props.
  • Column names avoid reserved words. Prefix them with the table's singular name, for example user_type rather than type.
  • Table changes go in a new add_*_to_*_table migration.

The thirteen folders

app/ contains exactly these: Casts, Console, Contracts, Enums, Helpers, Http, Mail, Models, Notifications, Providers, Rules, Services, Traits. Don't add a new base folder.
