Authentication

Every common way to sign in, each with its own switch. Turning a switch off closes the route as well as hiding the button.

Sign-in methods

MethodDefaultNotes
PasswordOnRegistration, sign-in, reset by emailed code, email verification by six-digit code
PasswordlessOnOne emailed code both registers a new account and signs in an existing one

Admins can use everything except social sign-in. Their two-factor and passkeys are managed on the admin profile.

Emailed codes

All four code flows (verification, reset, passwordless, account changes) share the same two limits, enforced by WithOtpGuard:

  • Five wrong guesses destroy the code. A six-digit code has a million possibilities, so an expiry alone isn't enough: with unlimited guesses, the whole range fits inside the window.
  • Another code can't be requested within 60 seconds. Without this, asking for a new code would undo the destruction.

The reset code is stored only as a hash, in Laravel's own password_reset_tokens table.

Hardening

  • Login throttle, keyed on the email and the IP address together, so nobody can lock out an address just by knowing it.
  • Password strength is configurable, and password history refuses a password this account has already used.
  • Captcha: Cloudflare Turnstile on each guest form rather than across the whole site. The widget and its validation rule are always added together by captchaRules(). The captcha stays off, whatever the switch says, until both Turnstile keys are set.
  • Social matching uses the provider's id first, so someone who changes their Google email isn't left with a second account. The last remaining way to sign in to an account can't be disconnected.
  • Remember-device tokens are stored only as a hash.

Passwords

Always write a password through PasswordSecurityService. updatePassword() sets the password and files the old hash away in one step. Assigning $user->password directly leaves a gap in the history, and the password in that gap is one the account could quietly go back to.

Passkeys follow the same idea: the package does the cryptography, and PasskeyService does the actual sign-in so the status check, audit trail and login alert all still run.
