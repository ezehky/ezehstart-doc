Data tables

One trait behind every listing, so a new listing is assembled from existing parts rather than built from scratch.

WithDataTable

Every part is optional. A page only gets the pieces it renders:

  • Row selection and a bulk-action bar. Bulk delete is only offered where tableDeletable() allows it.
  • A column manager that each account keeps for itself. It saves as each switch is flipped, and stores the columns that are hidden, so a column added later shows up for everyone.
  • Sorting and a date range.
  • Export to CSV, XLSX or PDF through ExportService. An account can only export what it can already see: the gate and the column list decide what goes in the file.

columnMaker(), filterMaker() and metricMaker() take named arguments rather than loose arrays, so a misspelled key causes an error instead of being silently ignored.

Components

<x-table.*>: columns, rows, cell, select, bulk-bar, active-filters, column-manager, export-modal, summary, empty.

Imports

WithFileImport reads CSV and XLSX one row at a time, using openspout so memory stays flat for files of any size. A bad row doesn't stop the run: each row is tried on its own, and the failures are reported back by row.

Status toggles

WithStatusToggle switches a row between active and inactive directly from the listing, through <x-util.e-badge>. It uses the same gate, activity log and toast as the edit form.
